# The assumption audit of the Milky Way verifier and gate (Supernova level 4, first item)

Security context: defensive security engineering under the charter in `CLAUDE.md`. This lists what the operating organisation's own entrance relies
on, so that each item becomes a runtime check or a test (DMP chapter 06, level 4: "every assumption the decision rests on is written
down and becomes a runtime check or a test").

Every row names the assumption, why the verifier needs it, and what carries it today. **Open** means nothing carries it yet; each open
row names the check that would. Status of the whole list: draft, first pass by lane L3b on 2026-10-25; A14 to A17 from the GRB-0001 run the same day.

| # | Assumption | Why it matters | Carried by | State |
|---|---|---|---|---|
| A1 | The transport keeps control data confidential | IM signs, it does not encrypt (DMP 04) | TLS 1.3 on both ports (DMP 05 "Transport encryption"); test `ImTransportTests.On_the_wire_neither_the_token_the_payload_nor_the_knock_appears_in_clear` | carried |
| A2 | The verifier's clock is right within `milkyway.im.clockSkew` | rules 7, 8 and 12 and the knock compare against it | nothing at runtime | **open**: the gate's health report should carry its own time and Doppler (or the monitoring module's time probe) should alarm when it differs from the domain's time by more than half the skew |
| A3 | Private keys stay where they are held (device TPM, Doppler's signer, the gate) | a stolen key signs as its owner | outside the verifier: Doppler's attestation and the TPM (lane L4); the verifier's side is that nothing it emits carries key material: `ImEvidenceTests.No_secret_key_token_or_payload_reaches_anything_the_gate_emits`, the wire capture of A1 | partly carried |
| A4 | Doppler's enrolment register tells the truth | rule 9 trusts it | Doppler's cross-check of the token ids Milky Way reports accepting (`MilkyWayHealth`, the `pair` group of `tools/verify`) | carried in the sandbox |
| A5 | The trust roots are the new authority's and nothing else | rule 4, the handshake and TLS all chain to them | custom root trust (the machine store is never read, `TrustAnchors`, `ImTls`); tests: foreign-authority certificates refused in IM and in TLS | **open at deployment**: the settings check should refuse a `milkyway.im.trustRoots` list that is empty or holds the old CA's root (its thumbprint as a setting) |
| A6 | The knock secrets are long and at most two | the knock is the first filter | `MilkyWaySettings.Validate` (runtime, at gate start); test `The_gate_refuses_to_start_without_a_knock_secret` | carried |
| A7 | The random numbers (challenge, session id, message id, nonces) cannot be predicted | a predictable challenge lets a response be prepared | the platform's cryptographic generator (`RandomNumberGenerator`); no test can prove unpredictability | accepted (platform) |
| A8 | The platform's TLS 1.3 and certificate parser are correct | TLS and every chain check use them | the platform's verdict is never used alone: every peer certificate is checked again by `ITrustAnchors` in its role; the fuzzer feeds certificate bytes through `ImChains.Load` | accepted (platform), narrowed |
| A9 | SHA-256, ECDSA P-256 and HMAC-SHA256 are secure | every signature and MAC | one algorithm, no negotiation (I4); a change is a new IM version | accepted (cryptography) |
| A10 | All doors share one verifier, so one replay memory | a message accepted on 443 must not be accepted again on 138 (I2) | `MilkyWayGate` holds one `ImVerifier`; both listeners must be served by one `GateTransport` of one gate | **open at deployment**: the wave-2 listener host must create one gate for both ports, and a test of the listener must send the same message to both ports and see `Replayed` |
| A11 | A clock that jumps does not open the replay window | rule 16 forgets ids by time | backwards: ids are kept longer (safe); forwards: an id is forgotten early, but rule 12 then refuses the message as stale; tests `BoundaryTests.Rule_16_an_id_is_still_remembered_at_sent_at_plus_the_skew`, `Rule_12_a_replay_after_the_window_is_refused_as_stale_so_forgetting_the_id_is_safe` | carried |
| A12 | A device signs a message only with its own key and only once per message id | replay keys on (key id, message id) | rule 16; ECDSA's second spelling `(r, n - s)` is refused (low-s rule), so a re-signed copy of the same body cannot pass as new: `ImLowSTests` | carried |
| A13 | Certificate-less connections cannot reach a session | before enrolment a machine shows no certificate | `GateSession` refuses their response before reading it (`TransportNoCertificate`), own limit `milkyway.im.maxUncertifiedConnections`; refusal suite | carried |
| A14 | Only Doppler holds a certificate in the role `ImTokenSigner` | rule 4 trusts the role, so any such certificate of the new authority signs tokens the gate accepts (GRB-0001 F1) | the CA plan (Doppler is the only requester of the role); Doppler's watch raises `alarm.milkyway.unknown_token` for an accepted token id it did not issue (shown in the GRB-0001 run) | **open**: wave 2 pins the accepted signer key ids from Doppler (`DopplerServer.AuthorityKeyIds`) in the verifier; until then the issuing CA endpoint's level (3) bounds the verifier's |
| A15 | Holders of the knock secret do not fill the knock memory | valid knocks share one memory of `milkyway.im.replayCapacity` nonces per skew window; full means no new session (GRB-0001 F2) | the secret is a gate, not an identity: rotation after misuse; messages of established sessions are not affected; knocks without the secret never reach the memory | **open**: a separate `milkyway.im.knockCapacity` and limits per source with the wave-2 listener |
| A16 | A device certificate that ends during a session does no harm until the session ends | the certificate is checked at the handshake only (GRB-0001 O3) | the token's lifetime (policy at most 24 hours, Doppler issues one hour) and rule 9 for every message; Doppler revokes registry and certificate together | carried |
| A17 | A device's certificate tells a stranger nothing worth having | the device's role check of the gate runs after TLS's handshake, so whoever terminates TLS sees the device certificate before the device refuses (GRB-0001 F3) | the subject is opaque (C3), the certificate is public by design, nothing of IM leaves the device before the gate is checked (GRB-0001 part 2) | accepted; wave 2 may pin the gate key ids a device receives at enrolment |

The four assumptions DMP chapter 04 named ("the transport provides confidentiality; the verifier's clock is right within the skew; the
private keys stay where they are held; the enrolment registry tells the truth") are A1 to A4. The rest came out of this audit.
